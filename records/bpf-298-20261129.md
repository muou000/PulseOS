# BPF 调度争用采样 · #298 · 2026-11-29

## 结论

本次实现把 RV64 与 LA64 的每 CPU tracepoint handoff 队列从 128 项扩大到 512 项，把单轮 tracepoint 消费批次从 16 项扩大到 256 项。队列现在记录 producer 入队、consumer 出队、当前积压和峰值积压，并把这些值加入 `/proc/pulse_bpf_stats` 与 recorder 诊断快照。原有 activation generation、稳定 task identity 和 disable 后的旧记录取消规则保持有效。

在同一台主机上完成的 RV64 精确 sysbench 对照只有一轮候选和一轮主线基线。候选保留 7,922 条记录，主线保留 640 条。候选 trace_full 为 6,121，主线为 3,398。候选的 tracepoint 取消合计为 635，主线为 256。两轮都保持真实有损状态并报告 `IncompleteError`。该单轮对照显示消费者进度改善，但不能据此宣称稳定的全局丢失率下降。

双架构 recorder mixed 回归均完成了真实 guest capture、关闭后无增长检查和 analyzer 解析。RV64 与 LA64 的 trace_full 都为 0，队列在关闭后分别剩余 4 和 6 条，capture 仍因其它会话质量条件保持 `IncompleteError`。

## 命令与 Query

双架构构建和门禁使用以下命令。

```sh
make rv APP_FEATURES="qemu bpf-trace"
make la APP_FEATURES="qemu bpf-trace"
make test APP_FEATURES="qemu bpf-trace"
cargo test -p pulse_bpf_schema --tests
cargo test -p bpf --lib -- --test-threads=1
cargo test -p pulse_syscalls --lib -- --test-threads=1
```

精确 workload 的 guest 控制命令如下。

```sh
/bin/taskset -c 1 /usr/bin/sysbench --threads=4 --events=0 --time=30 \
  threads --thread-yields=100 --thread-locks=1 run
bpf-record --events sched --cpus 1 --duration-ms 200 --buffer-pages 256 \
  --kernel-elf /boot/kernel.elf --output trace.pbcapture
```

关闭阶段核对 `RECORD QUIESCENT inflight=0`、`RECORD NO_GROWTH before=... after=...`，然后由 guest 原样导出 capture。每个报告使用完整 capture，不进行事后事件重编码。

## 成本与实现检查

- `EventRecord` 为 96 bytes。每 CPU 队列从 128 到 512 项，8 CPU 的队列槽位增加 294,912 bytes。队列诊断原子量增加 128 bytes。worker 批次从 16 到 256 项，栈数组增加 23,040 bytes。
- RV64 候选 ELF 的 `CPU_QUEUES` 符号为 393,728 bytes，主线为 98,688 bytes，差值为 295,040 bytes。该差值包含新增 queue diagnostics 原子量。
- 诊断行新增 `trace_dequeued`、`trace_queued`、`trace_high_water` 和 `trace_queue_capacity`。旧 `DropStats` API 保持原字段与 reset 语义。
- 队列单测覆盖了 FIFO、generation、分批 drain、剩余积压和 high-water 统计。`pulse_syscalls` 的 244 项单测、`bpf` 的 3 项单测和 schema 测试全部通过。

## 原始产物与边界

完整 guest log、capture、analyzer JSON、内核副本和镜像副本留在各工作树的 `tests/bpf_record/runs/` ignored 目录中。报告只提交摘要与 SHA-256，摘要不能替代原始 capture 的完整回放。

本次没有完成 issue 要求的多轮交错 RV64/LA64 精确 workload 矩阵，也没有获得附着与未附着 sysbench 吞吐的统计样本。主线第二轮精确 workload 在 capture 导出后 guest 收尾阶段超时，未纳入比较表。
