# PulseOS io_uring 双架构回归与 fio + BPF 采样分析

日期：2026-11-22。关联任务：[完成 io_uring 双架构全量回归验收、构建脚本沉淀与 fio + bpf-record 异步性能实证](https://github.com/muou000/PulseOS/issues/240)（Part of [#224](https://github.com/muou000/PulseOS/issues/224)；设计/验收依据 [#234](https://github.com/muou000/PulseOS/issues/234)、[#228](https://github.com/muou000/PulseOS/issues/228)、[ADR-0007](../docs/adr/0007-io-uring-hybrid-async-execution-engine.md)、[ADR-0008](../docs/adr/0008-linux-io-uring-v1-compatibility-tier.md)）。

## 结论

- **四层功能回归门禁在 RISC-V 64 与 LoongArch64 双架构全部通过**：
  - 宿主单测通过：`pulse_user_abi` 36 项、`axtask --lib --features "test multitask"` 14 项、`pulse_io_uring_core` 35 项、`pulse_syscalls --lib -- --test-threads=1` 235 项；四目标构建 `make vf2`、`make ls2k1000`、`make test` 全部退出码 `0`。
  - 双架构 `-smp 8` `guest-checks`（RV64 `ad8198`、LA64 `6eb810`）全部打印 5 项 `[IO_URING_RSRC_GUEST] ... PASS`（含并发 `munmap` + `close(ring_fd)` 五步回收物理页引用从 `3 -> 2 -> 2 -> 1 -> 0` 精确归零）。
  - 双架构 `-smp 8` `functional`（RV64 `d3d80e`、LA64 `fe6e3e`）全部通过：LTP `io_uring01..03` 均 `TPASS` (`rc=0`)，`KCONFIG_SKIP_CHECK=1 io_uring04` 均 `TCONF` (`rc=32`)；`liburing-2.9` (`08468cc3`) 54 项共 `53 PASS + 1 SKIP + 0 FAIL`（`run_all.sh` 退出码 `0` 仅允许 `ooo-file-unreg.t` 返回 `rc=77`，因 `#228` §2.6 / `ADR-0008` 明确拒绝 `IORING_REGISTER_FILES2` 返回 `-EINVAL` 并触发上游 `T_EXIT_SKIP`）；`smp_stress` 4 组并发压测全部 `PASS`。
- **`fio-3.39` + `syscall_count_bench` 无插桩性能指标达标，Path 1 内联批处理优化带来明确正向收益**：
  - 系统调用折减（等量 `16,384 × 4 KiB = 64 MiB` 读取）：`O_DIRECT qd=16` 达 **15.37x**（RV64，`1,066` vs `16,384`）与 **13.51x**（LA64，`1,213` vs `16,384`）；Cached `qd=32` 双架构均达 **32.00x**（`512` vs `16,384`）。
  - 异步队列并发度（`O_DIRECT qd=16` 配合 `--iodepth_batch_submit=8 --iodepth_batch_complete_min=1 --iodepth_batch_complete_max=8`）：`IO depths >= 8` 占比分别为 **100.03%**（RV64，`fio` 桶四舍五入合计：`8=0.1%`、`16=99.933466%`）与 **100.00%**（LA64，`8=97.95501%`、`16=2.04499%`），带宽分别达 `9.388 MiB/s`（对比 `psync` `5.411 MiB/s`，+73.50%）与 `12.223 MiB/s`（对比 `psync` `6.799 MiB/s`，+79.78%）。
  - Cached 预热 `qd=32` 吞吐增益（`4 MiB` 常驻 working set 下在 `5s` 窗口内循环读）：RV64（`9c173d`）由 `psync 136.366 MiB/s` (`34,909.80 IOPS`) 提升至 `187.063 MiB/s` (`47,888.02 IOPS`，**+37.18%**）；LA64（`363844`）由 `209.665 MiB/s` (`53,674.27 IOPS`) 提升至 `278.544 MiB/s` (`71,307.34 IOPS`，**+32.85%**)。优化前 RV64 在 `64 MiB` 文件受 `axfs::DISK_FILE_CACHE_SOFT_LIMIT = 1024` 页（`4 MiB`）驱逐且无 Path 1 内联快路径时曾退化为 `-59.14%`（`29.815 -> 12.182 MiB/s`），LA64 优化前 `4 MiB` 常驻仅 `+18.52%`（`221.632 -> 262.672 MiB/s`）。
  - 预期退化与 TCG 虚拟化噪声：单队列深度 `direct_uring_qd1`（RV64 `4.202 MiB/s`、LA64 `4.524 MiB/s`）低于同线程 `direct_psync`（RV64 `5.411 MiB/s`、LA64 `6.799 MiB/s`），符合单请求无法掩盖 Future 编排与调度开销的预期；此外 5 秒定长窗受 QEMU `-smp 8` TCG 宿主调度噪声影响存在波动（LA64 三次同类运行实测 cached 增益分别为 `e5e0a0` `+24.44%`、瞬态抖动失败的 `b0653e` `+16.86%`、复测通过的 `363844` `+32.85%`；RV64 为 `9d3ed9` `+21.28%` 与 `9c173d` `+37.18%`）。
- **`bpf-record` 与 `FlameGraph`（`cpu,sched` + `--callchain fp`）验证了 `syscall_handler` 热点转移与阻塞切换大幅下降**：
  - Cached 负载下（Path 1 零 Future 内联快路径）：`syscall_handler` 叶子样本占比在 RV64 从 `34.21%`（`91/266`）降至 **`1.52%`**（`4/263`，降幅 **22.51x**），在 LA64 从 `46.91%`（`129/275`）降至 **`0.75%`**（`2/265`，降幅 **62.55x**）；`try_inline_fast_path_read` 占据包容性热点 **73.76%**（RV64）/ **76.60%**（LA64），`spawn_boxed_and_poll_once` 样本为 **0.0%**，目标线程除启动首轮 `~100 ms` 等待外零每 I/O 阻塞切换（`190,624` / `337,888` 次 I/O 仅 `blocked_waits=1`）。
  - `O_DIRECT` 负载下（Path 2 异步轮询与批量收割）：目标 `fio` 线程阻塞等待次数在 RV64 从 `direct_psync` 的 `1,272` 次（`343.43 ms`）降至 `direct_uring_qd16` 的 `33` 次（`102.55 ms`，**38.55x** 下降），LA64 从 `5,071` 次（`663.93 ms`）降至 `72` 次（`120.81 ms`，**70.43x** 下降）；`spawn_boxed_and_poll_once` 占 `68.38%`（RV64）/ `61.56%`（LA64）包容时间。LA64 `direct_uring_qd16` 下 `syscall_handler` 叶子占比为 `2.51%`（`9/359`）高于 `direct_psync` 的 `1.25%`（`3/240`），原因在于 `direct_uring_qd16` 以 `1.84x` IOPS 持续驱动批量提交/收割并消除了高频阻塞切换。
- **质量与归因边界声明**：8 份 `bpf-record` capture 均标注 **`Status: IncompleteError`** 与 **`Attribution Claim: Disallowed`**（`capture_complete=false`, `attribution_complete=false`），存在 `timer_busy`、per-source `skipped`/`cancelled`、RV64 `direct_uring_qd16` 的 `system trace_full=9395` 及 LA64 `direct_uring_qd16` 的 `sink:0 transport_lost=1512`（与 `source:* emission_gap=1512`）；导出筛选了事后主导工作负载线程 `--pid --tid --mode kernel`，所有导出样本为陷阱边界截断的 `partial_chain`。上述热点与调度统计仅反映已采样且未丢失的局部区间，**不可**作完整全局归因。

- **Query 定义与选择理由**：
