# Recorded #195 evidence

> **Retention update — 2026-11-16:** The raw `.tar.gz` bundles described below
> have been removed from the current tree. Retained indexes, hashes, counts and
> replay reports record historical verification; they do not provide a complete
> replay from this checkout. Bundle names and links below are historical references.
> The old replay commands require complete bundles held separately; metadata
> cannot reconstruct their bytes. For new evidence, follow the
> [fresh-run instructions](../../README.md) and keep raw output out of Git.
> See the [sampling evidence retention policy](../../../../docs/sampling-evidence-retention.md).

Eight positive RV64/LA64 runs retain 38 actual guest capture files containing
43,633 records. All remain partial. `index.json` hashes every archive and member;
`replay-report.json` was generated by extracting the committed bundles into
fresh temporary directories and checking original serial-file bytes with the
final analyzer. Boot kernels and deployed recorder/fixture ELFs are retained
inside positive bundles; rootfs images are identified by SHA-256 and are not
duplicated here.

| Bundles, for both architectures | Qualified evidence |
|---|---|
| `*-full.tar.gz` | CLI, mixed/duplicate sources, lifecycle, limits, rollback and write failure |
| `*-recovery.tar.gz` | Stable identity across real nonleader exec, actual stop failure, task sampling |
| `*-benchmark.tar.gz` | Revised three-stage measurements including actual baseline/detached proc snapshots |
| `*-existing.tar.gz` | Image-installed sh/dd/sleep, real CPU/scheduler/fault records tied to execution TIDs |
| `*-task.tar.gz` | Separate existing sampler's Link and ioctl final-dup-close checks |

The initial full runs used source metadata revision 1 and incomplete benchmark
instrumentation. Their functional results remain valid; use `--functional-only`
when replaying them. Benchmark qualification comes exclusively from the later
`*-benchmark` runs. Revision 2 task binding is exercised by the recovery runs.
Unknown identities in revision 1 are not upgraded during replay.

Example from the repository root:

```bash
cargo build -p bpf-analyzer
replay_dir=$(mktemp -d)
tar -xzf tests/bpf_record/evidence/195/riscv64-recovery.tar.gz -C "$replay_dir"
python3 tests/bpf_record/verify.py "$replay_dir"
```

For full bundles append `--functional-only`. Legacy task and rejected bundles
have their original logs/results and are not inputs to the generic verifier.

The three `*-rejected-*` bundles are unmodified failures: an ANSI-prefixed
framing marker, byte interleaving from concurrent console logs, and an
image-shell SIGTERM exit status during workload cleanup. They are not positive
captures and no missing bytes were reconstructed. The harness strips ANSI
control sequences only, preserves CRC/offset checks, and replays control/file
output after the external workload stops. Kernel logging remains enabled.
